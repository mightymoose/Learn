Aggregation

One page. Print it. The argument order and the condition forms, which are the two things people look up again and again.

Plain totals

FormulaReturns
=SUM(Sales[Revenue])The total
=AVERAGE(Sales[Revenue])The mean, ignoring empty cells
=COUNT(Sales[Units])How many cells hold a number
=COUNTA(Sales[Rep])How many cells are not empty, text included
=MAX(Sales[Revenue])The largest value
=MIN(Sales[Revenue])The smallest value

COUNT counts numbers. COUNTA counts anything. Getting a surprisingly low count is nearly always this.

Conditional totals

Argument order is the thing to get right. The range to add comes first, then condition pairs.

=SUMIFS(add_this, test_this, must_equal, test_this_too, must_equal_too)

QuestionFormula
Total for one region=SUMIFS(Sales[Revenue], Sales[Region], H11)
How many rows match=COUNTIFS(Sales[Region], H11)
Average of matching rows=AVERAGEIFS(Sales[Revenue], Sales[Region], H11)
Largest matching value=MAXIFS(Sales[Revenue], Sales[Region], H11)
Two conditions at once=SUMIFS(Sales[Revenue], Sales[Region], H11, Sales[Price], 4.5)

COUNTIFS has nothing to add up, so it starts straight in on condition pairs. Every other function in the family takes its range first.

Use the S

The older SUMIF and AVERAGEIF, with no S, take their arguments in the opposite order. Use the S versions always, even for one condition. One argument order is easier to remember than two.

Condition forms

A condition is not limited to an exact match. Comparisons and wildcards go in quotes.

ConditionMatches
H11Whatever that cell holds. The preferred form
"North"Exactly North. Case is ignored
">500"Greater than 500
">="&H11At least the value in H11. Note the ampersand
"<>North"Anything except North
"N*"Starts with N. The star means any characters
"?????"Exactly five characters. Each mark is one character
""Empty cells

The ampersand form is the one people get wrong. A comparison built from a cell has to be glued together as text, so it is ">="&H11 and never ">=H11", which looks for the literal characters.

When a total comes out zero

CheckWhy
Trailing spaces in the data"North " does not equal "North". Use TRIM
Numbers stored as textThey sit left in the cell and match nothing numeric
The two ranges differ in lengthSUMIFS needs matching shapes and errors otherwise
The criteria cell is emptyAn empty criteria matches nothing, silently
You swapped the first two rangesThe SUMIF and SUMIFS argument order trap

Always add the check

Put this in a spare cell beside any summary block. It should read zero forever.

=SUM(I11:I13)-SUM(Sales[Revenue])

If the parts stop adding up to the whole, a category is missing or misspelled. A summary that cannot be checked is a summary nobody should trust, yours included.
