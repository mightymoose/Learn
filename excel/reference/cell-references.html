The four forms

A dollar sign locks whatever comes immediately after it. That is the whole rule.

FormNameWhen you copy itUse it for
H1RelativeColumn and row both moveThe normal case, row-by-row work
$H$1AbsoluteNothing movesA rate, a constant, one input cell
$H1MixedColumn stays, row movesFilling across, reading down one column
H$1MixedRow stays, column movesFilling down, reading across one row

The test, applied to every reference

Ask the two halves separately, then put a dollar sign in front of every no.

As this formula gets copied, should the column letter change?

Keystroke

Put the cursor on a reference inside the formula bar, then press F4 to cycle the four forms.

H1 → $H$1 → H$1 → $H1 → H1

On many Macs this is Command T. On laptops with media keys you may need Fn F4.

Structured references, from Tables

Inside a Table these replace the forms above. They carry no row numbers, so they cannot break when data grows. See lesson 3.

FormMeans
Sales[Revenue]The whole Revenue column, however long it gets
[@Units]Units on this row, used inside the Table
Sales[#Headers]The header row only
Sales[#Totals]The total row only
SalesThe data body, no headers, no totals

Symptoms and causes

What you seeAlmost always
First row right, all others zeroA reference that should be absolute is relative
Every row shows the same numberA reference that should be relative is absolute
#REF!The referenced cell was deleted, not just emptied
#VALUE!Arithmetic hit text, often a number stored as text
#####Nothing is wrong. The column is too narrow
Formula shows as textThe leading equals sign is missing, or the cell is formatted as Text

Two habits worth keeping

Build the reference by clicking the cell rather than typing its address. It is faster and it cannot produce a typo that still calculates.

When a filled column looks wrong, click a cell in the middle of it, never the first one. The first cell is right by construction, which is why the error hides there.
